What's actually in a QR code

A QR code is a grid of black and white squares called modules. Only some of them carry your data — the rest are structure the scanner needs before it can read anything:

  • Finder patterns — the three big squares in the corners. They let a scanner locate the code and work out its rotation, which is why a QR code reads upside down just as happily as the right way up.
  • Timing patterns — the alternating row and column between the finders, which tell the scanner how wide one module is.
  • Alignment patterns — the smaller squares that appear from version 2 onward, correcting for perspective when you scan at an angle.
  • Format and version information — the error correction level, the mask, and (from version 7) the version number, each stored twice so damage to one copy doesn't matter.

The version is the size: version 1 is 21×21 modules, and every version after that adds four modules per side, up to version 40 at 177×177. This tool picks the smallest version your content fits into, so a short link stays a small, chunky, easy-to-scan code.

Which error correction level to pick

QR codes use Reed–Solomon coding, so a code still reads with part of it missing. You choose how much of that redundancy to buy — and you pay for it in capacity:

LevelRecoverableBytes at version 10Good for
L~7%271Clean digital use — a slide, a web page, an email
M~15%213The sensible default for print
Q~25%151Stickers, packaging, anything that gets handled
H~30%119Harsh environments, or a logo covering the middle

Higher isn't automatically better. More redundancy means more modules for the same content, so at a fixed print size each module gets smaller — and past a point that hurts scanning more than the extra correction helps. Start at M and move up only if the code will be damaged, curved, or partly covered.

The quiet zone is not optional

The blank margin around a QR code is part of the specification — four modules on every side. It's what tells the scanner where the symbol ends. Codes that fail to scan against a busy background are very often codes someone cropped the quiet zone off. The slider above defaults to 4 for that reason; drop it only if something else in your layout is already providing the margin.

Dark on light, always

Scanners look for dark modules on a light background. Invert that — light modules on dark — and a lot of readers simply won't see the code, no matter how good the contrast is. Coloured codes are fine as long as the modules stay clearly darker than the background; this tool warns you when they don't.

What the payload formats look like

A QR code holds plain text. The "types" above are just conventions that phones recognise and act on:

{% raw %}# Link — any URL with a scheme
https://example.com

# Wi-Fi — T is the auth type, S the SSID, P the password
WIFI:T:WPA;S:MyNetwork;P:s3cr3t;;

# Email
mailto:someone@example.com?subject=Hello&body=Hi%20there

# SMS
SMSTO:+95912345678:Message text

# Phone
tel:+95912345678

# Contact card
BEGIN:VCARD
VERSION:3.0
N:San;Thet Htoo;;;
FN:Thet Htoo San
TEL;TYPE=CELL:+95912345678
EMAIL:me@example.com
END:VCARD{% endraw %}

Inside a Wi-Fi payload, the characters \ ; , : and " have to be backslash-escaped — this tool does that for you, so a password full of punctuation still works.

A word on safety

A QR code is opaque to the person scanning it: you cannot tell where it leads by looking at it. That's exactly why "quishing" works — a sticker over the code on a parking meter, a fake code in a phishing email, and the victim never sees the domain until they're already on it. Two habits are worth keeping:

  • Read the URL preview your phone shows before opening it, and treat a shortened link on a physical sign as a small red flag.
  • Check physical codes for tampering. A sticker on top of a printed code is the entire attack.

If you're generating a code for a Wi-Fi network, note that the password is stored in it as plain text. Anyone who photographs the code has the password — which is fine for a guest network on a poster, and a bad idea for your main one.

How this page builds the code

The encoder is written from the specification and runs entirely in your browser: it picks the smallest workable version, encodes the content in numeric, alphanumeric or UTF-8 byte mode depending on what you typed, adds Reed–Solomon error correction, interleaves the blocks, then tries all eight mask patterns and keeps whichever scores best under the standard's penalty rules. No request is made, so nothing you type here — a Wi-Fi password especially — is ever sent anywhere.

PNG exports are drawn at a whole number of pixels per module, which is why the size dropdown lands near the number you pick rather than exactly on it. A resampled QR code has blurred module edges and scans badly; a slightly different size doesn't.

Generating them elsewhere

{% raw %}# Linux / macOS — qrencode
qrencode -o code.png -s 8 -m 4 -l M "https://example.com"
qrencode -t ANSIUTF8 "https://example.com"   # straight into the terminal

# Python
python3 -m pip install segno
python3 -c "import segno; segno.make('https://example.com', error='m').save('code.png', scale=8)"

# Node.js
npx qrcode "https://example.com" -o code.png

# PowerShell
Install-Module QRCodeGenerator -Scope CurrentUser
New-PSOneQRCodeText -Text "https://example.com" -OutPath code.png{% endraw %}
